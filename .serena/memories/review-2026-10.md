# Review 2026-10-10 — response bounds and PHP parity

Found while the gateway (gsoultan/panmail) was reviewed end to end; branch
`claude/review-perf-fixes-q6hegx`. Requirements now written in `docs/PRD.md`.

- **Go drained the whole remainder of a response.** The deferred
  `io.Copy(io.Discard, res.Body)` ran after the 1 MiB `LimitReader` read, so a
  proxy's endless error page or a gzip bomb held `Send` until the HTTP client's
  timeout — forever with `&http.Client{}` and no deadline. Now
  `io.CopyN(…, maxDrainBytes = 64 KiB)`. Test:
  `TestSendDoesNotDrainABodyThatNeverEnds` (3s stream, must return in <2s).
- **PHP threw TransportException for any body over 1 MiB, whatever the
  status.** A 429 behind a long proxy page read as an unknown outcome, so
  `rateLimitRetries` never applied — a Go/PHP parity break, since Go already
  truncated and classified. `CurlTransport` now keeps the first MiB and
  returns the response for status ≥ 300; a 2xx over the bound still throws.
  Tests: `testAnOversizedRefusalKeepsItsStatus` (server route
  `/huge-refusal`).
- **Error messages carried up to 1 MiB of proxy HTML.** Both clients cut to
  4 KiB on a character boundary. PHP does it without mbstring (not a declared
  requirement) by dropping the last multibyte sequence with a byte regex.
  Tests: `TestALongProxyPageIsCutToALogLine` /
  `testALongProxyPageIsCutToALogLine`.
- **PHP opened a new cURL handle per request** — a TCP + TLS handshake per send
  and per listing page. Now one handle per transport, `curl_reset` between
  requests (it clears the callbacks holding the previous request's buffers;
  the connection cache survives). Test: `testOneTransportServesRequestAfterRequest`.

Verification gap at the time: composer could not download dependencies in the
cloud container (GitHub zipballs refused), so phpunit and PHPStan did not run
there; the PHP changes were exercised with standalone scripts against
`php -S tests/server.php`. Run `composer test` and `composer analyse` locally.
golangci-lint in that container was built with Go 1.25 and refused the 1.27
module — an environment problem, not a lint failure.
